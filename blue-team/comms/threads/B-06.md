# Thread B-06: observe(context, tools) entry point that runs detection, proposals, and the report

### 2026-10-01T17:09:20Z | claude | proposal

**Summary:** Add backend/app/agents/blue/observe.py with `async def observe(context, tools)`, the blue module boundary in the shared contract. It builds a frozen, allowlisted blue context from the context argument. It runs the existing pieces in order: detect_suspicious_access, propose_session_revocations, propose_ownership_patch (patch ID from the fixed defenses/patches registry), and build_incident_report. It returns a JSON-ready result shaped like the contract: alerts (Alert.event_data), defense proposals (DefenseProposal.event_data), evidence refs, skipped records, a short summary of actions taken, the data_source label and the report. It adds no new detection or proposal logic, makes no network calls and needs no new dependencies.
**Security:** Trust boundary: observe is where core hands data to blue, so it must decide what blue can see. (1) Allowlist the context. Accept only target_id, target_version, data_source, telemetry, access_policy, previous_defenses, budgets, and an optional assessment_id and generated_at. If any other top-level key is present, such as events, candidates, findings, ground_truth, red_* or verdicts, raise ContextError. Silently dropping it would hide a core bug that leaks red or evaluation data into blue. Never forward the raw context object to the helpers. (2) Run the incident report without referee or red events. The contract does not give blue referee verdicts. observe passes only blue's own alert.created and defense.proposed data, plus previous_defenses entries of type defense.applied or defense.failed (system outcomes), into build_incident_report. The report status can therefore only be open, contained or awaiting_retest. It can never be resolved, so blue cannot mark its own fix as verified. The full report with Recover verdicts stays a core- or CLI-side build (report.py). (3) Scope telemetry. Records whose target_id or target_version differs from the context are moved to skipped with a reason, never alerted on, so a version mix-up cannot raise a false alert or hide a post-patch alert. (4) Fail closed on policy. A missing or malformed access_policy produces no alerts and a structured error. It never falls back silently to PRIVATE_ORDERS_POLICY, which would let detection run against the wrong policy without anyone noticing. A policy is accepted only if its id and owner_only_actions are well-formed strings. (5) Credentials. Proposals carry only session_ref and patch_id/base_version (existing behavior). Unexpected telemetry fields (token, cookie, authorization, password, api_key, secret) are never copied into alerts or the summary. The report's existing _sanitize redacts them before hashing. (6) Patch source. The manifest is loaded only via load_patch_manifest with a constant ID (ownership-fix-001). No path or patch ID comes from the context. A draft manifest stays labeled draft. (7) tools are not used for network access in M1. observe calls no HTTP tool and runs no executor. Budgets and cancellation are enforced outside the model. If budgets are present and max_steps or timeout_seconds is 0 or less, or tools reports cancellation, observe returns an empty, labeled result. Unsafe failure modes to guard against: an exception halfway through returns partial proposals without alerts (avoid by building everything first, then returning once); summary text including red-sounding conclusions (it reports counts and IDs only); a fixture or recorded run labeled live (pass context data_source through unchanged and require it to be one of v1 data_sources).
**Approach:** 1. observe.py: a frozen dataclass BlueContext and parse_context(context) -> BlueContext. It validates the allowlist, data_source in {fixture, live, recorded}, non-empty target_id/target_version, that telemetry is a list, the policy shape, and that previous_defenses is a list of mappings or DefenseProposal. 2. `async def observe(context, tools=None) -> dict`. Steps: ctx = parse_context(context); check budgets and cancellation (tools may be None or expose `cancelled()`); split telemetry into in-scope and off-target (skipped); result = detect_suspicious_access(in_scope, policy); revocations = propose_session_revocations(result.alerts, ctx.previous_defenses); patch = propose_ownership_patch(result.alerts, load_patch_manifest(OWNERSHIP_PATCH_ID), ctx.target_version, ctx.previous_defenses) inside try/except PatchManifestError, which records a structured note and does not raise; report = build_incident_report(... events=blue_events + system outcome events only, generated_at=ctx.generated_at). generated_at comes from the context, or a clock passed in tools, so tests stay deterministic. 3. Return {schema: 'range.blue.observe/v1', target_id, target_version, data_source, alerts:[...], defense_proposals:[...], evidence_refs: ['telemetry:<request_id>' for alerted requests], skipped:[{request_id, reason}], summary, report (or None), notes}. The summary is one or two sentences of counts and actions, for example 'Detected 1 cross-user read alert; proposed 1 session revocation (containment) and 1 patch awaiting retest.' Before returning, check that every alert payload has v1 alert.created.required and every proposal has defense.proposed.required. Use a local constant mirroring v1.json, or load shared/contracts/v1.json read-only, and raise on a mismatch. 4. Export observe and ContextError from __init__.py. Update the README section 'Not yet' and add a short observe section covering the context allowlist and what the report excludes.
**Tests:** New backend/tests/blue/test_blue_observe.py (unittest, using asyncio.run). Positive: (a) The shared fixture telemetry plus a policy context yields one cross_user_read alert, one revoke_session proposal labeled containment, and an apply_patch proposal labeled remediation with patch_status draft. data_source stays 'fixture' and report.status is 'open'. (b) Output keys satisfy v1 required keys for alert.created and defense.proposed. (c) Determinism: two calls with the same context return identical output. Negative controls: (d) Alice reading her own order gives no alerts, no proposals and report None. (e) Denied 403 cross-user attempts give no alert. (f) Context with an extra 'events' key holding finding.candidate or finding.verified raises ContextError. The same applies to 'ground_truth' and 'candidates'. (g) Missing or malformed access_policy gives no alerts and an error, with no fallback to PRIVATE_ORDERS_POLICY. (h) Telemetry for another target_id or target_version is skipped, not alerted. (i) A previous_defenses revoke for the same session_ref yields no duplicate revocation. (j) Telemetry records carrying token, cookie or authorization fields leave no such keys anywhere in the output (reuse blue_test_helpers.secret_keys). (k) Even with a retest.completed 'passed' smuggled into previous_defenses, report.status is never 'resolved' and the Recover section is empty. (l) data_source 'liveish' or missing raises ContextError. (m) An exhausted budget (max_steps 0) or cancelled tools returns an empty result with a summary that says why, and the detector and loader are never called (patch them to assert). (n) An unreadable patch manifest (patches_dir monkeypatched to an empty temp dir) still returns alerts and revocations, adds a note and raises nothing. Run: cd backend && python -m unittest discover -s tests/blue -v; python scripts/check_handoff.py --self-test; git diff --check.
**Efficiency:** About 120 lines of glue code: everything else is reuse of the existing detection, proposals, patches and incident modules. The output reuses existing event_data payloads, so core can emit alert.created and defense.proposed events without mapping. B-07 (stand-in executor and end-to-end flow) can call observe directly instead of chaining helpers, which saves Codex from reimplementing the order of steps. report.py could later switch to observe for the detection half, but leave it unchanged now to keep the diff small. - tools stays inert: observe reads only cancelled() and now().
- generated_at comes from the context or tools.now(). If neither is supplied and a report is needed, ContextError is raised; the code never reads the system clock.
- Before returning, alert and proposal payloads are checked against the v1 required keys, using constants that a test keeps in sync with v1.json.
